# Static furniture and plants

This is an original, explicit-family geometry planner. It is not a catch-all for frame-important tiles. The planner lives in `core/static-furniture-next.mjs` and is integrated into the shared renderer.

`planStaticFurnitureNext(region, x, y, tile, options)` returns `null` for a different family, `{commands:[...]}` for implemented static geometry, or `{unsupported:reason}`. An incomplete lighting fixture returns `{commands, partial:true, unsupported, dependencies}`: its body is reviewable, but the caller **must reject the entire result whenever `unsupported` is present**. A nonempty command list alone does not mean that an object is fully supported.

Each command carries the actual texture name, source crop, pixel offsets, mirror flag, tile type, optional paint override and optional premultiplied vertex color. Paint, asset bounds, visibility, compositing and viewport clipping remain the caller's responsibility. The module never changes tile records or serialized world bytes and never returns a fake empty successful result.

## Verified behavior

- Explicitly inspected ordinary furniture segments retain their saved 16×16 crops. This includes hearts, shadow orbs, bottles, books, signs, looms, kegs, paintings and several workstations. These are source-default dimensions within a fixed allowlist, not dimensions inferred from the frame-important bit.
- Anvils, demon altars, hellforges, traps, ordinary and special boulders, and fallen logs use 16×18 crops. Detonators, second-generation containers and tables extend their bottom saved row to 18 pixels. The tinkerer workstation extends nonzero rows to 18 pixels.
- Floor offsets are explicit per family. Pressure plates and levers use height 18 at Y +2. Switches distinguish floor, left-wall and right-wall placement. Geysers distinguish their attachment orientation.
- Beds and bathtubs wrap vertical style pages every 2,016 pixels into 144-pixel-wide atlas columns. Candelabras use 72-pixel columns and hanging lanterns use 36-pixel columns. Pianos, dressers and benches wrap horizontal style pages every 1,998 pixels into 36-pixel rows; bookcases use 72-pixel rows. Grandfather clocks wrap at X 2,016 into 90-pixel rows. Lamps wrap at Y 1,998 into 36-pixel columns.
- Non-flame furniture with Martian or Meteorite glow styles adds the source's separate unpainted mask. The baseline freezes Martian brightness at its initialized value 1, giving vertex color `(250,250,250,0)`; Meteorite masks use `(100,100,100,0)`. These premultiplied colors must not be treated as zero-opacity sprites.
- Campfires use animation frame zero. A saved extinguished row adds 252 to atlas Y. Lit campfires add `Flame_15.png`, with the source's style-dependent vertex colors and paint disabled. Rainbow campfire color is frozen to the initialized red disco state.
- Bamboo and cattails use saved 16×16 crops at Y +2 and mirror at even absolute world X. Rising seaweed uses Y +2 without that mirror. Wind and world-position push are zero.
- Coral uses 24×26 crops at (−4,−8); beach piles use 20×20 at (−2,−2). Garden gnomes use 26×18 at X −5, with top-row Y −2 and bottom-row Y 0. Dye plants use 32×38 at X −8; their normal Y offset is −20, while frame X 238 uses −6. The cactus-fruit frame X 204 is rejected until cactus-root biome resolution is available.
- Sea oats sample the tile immediately below; oasis plants use the source's inclusive **four-column** ground sampling interval, despite their three-cell width. Biome ties prefer Hallow, then Crimson, then Corruption. Sea-oat coastal variants require known world width and beach distance. A missing sampling halo is an error, not a neutral-biome assumption.
- The two Palworld objects, 751 and 752, are single oversized sprites in the source. This planner partitions each sprite by its saved tile cells, preserving overhangs and origin-cell paint. The actual 752 atlas is 38×36 while the source requests a 36×38 crop. Two explicit copies of its last source row implement the native clamp sampler for the extra bottom pixels; no out-of-range Canvas crop is used. It does not hide the other three cells or draw four overlapping copies. Type 751's seven-way source-Y phase uses the object's absolute origin, making it stable across render chunks.

## Beams and columns

Types 124, 561 and 574–578 do not save atlas coordinates in this world format. The planner reconstructs all cardinal masks and the ordered full-mask diagonal cutouts from the eight surrounding cells. Only the same beam material connects horizontally. Wooden Beam 124 additionally joins solid, non-platform tiles above and below. Source solidity initialization facts include its three initialization ranges; they are not inferred from the presence of a texture.

Source slope directions, upper/lower half-block rules, actuation and invisible-coating parity are respected for neighbors. A present but actuated neighbor still contributes to framing. Missing halo cells and unknown tile IDs/shapes are rejected. Wooden-beam attachment to runtime-toggled active stone 379 is rejected because the WLD alone does not supply that transient solidity.

The unsaved random `frameNumber` is fixed to variation zero and labeled `approximate-static-beam-variation-zero`. This is a valid atlas variant, not a claim of identical random variation to a running game. Types 124 and 574–578 use 16×18 crops. Marble Column 561 uses 16×20, Y −2, and remaps 18-pixel frame rows to a 22-pixel atlas pitch. Nonzero shapes of the beam itself are rejected because the source has additional exposed-edge drawing beyond a generic shape clip.

## Herb state from the WLD header

Tile 82 is ImmatureHerbs, 83 is MatureHerbs, and 84 is BloomingHerbs. Mature herbs can draw from atlas 84 depending on species and saved world conditions. `readWorldHerbContext(world)` walks the header serialization for supported versions 269–326, accounting for the second saved date from version 284 and the additional world flag from version 302. It validates dimensions, booleans used by herb selection, numeric ranges, and the header section boundary. It does not search the byte buffer for plausible offsets.

The returned context should be attached as `region.herbContext`, or passed as `options.herbContext`. It contains day/night, time, moon phase, blood moon, rain, cloud alpha, world surface, Remix status and dimensions. The source's post-load assignment makes cloud alpha equal to the saved maximum rain value. Missing context is rejected for species whose bloom state depends on it. Blinkroot and Shiverthorn do not perform this conditional mature-to-blooming atlas replacement and therefore do not require that context.

Blooming Fireblossom also changes vertex color using a runtime UI pulse. It requires an explicit `options.mouseTextColor` in 0–255 unless the tile is fullbright; missing pulse information is rejected. The fullbright scene baseline leaves Shiverthorn's light-increase override at white.

The public example's header yields night, time 15,088, moon phase 6, no blood moon, no rain, cloud alpha 0, and world surface 649. Those are parsed values, not a fabricated default day.

## Explicit unresolved visual dependencies

Lighting fixtures 33, 34, 42, 49, 93 and 100 retain an explicit unsupported result because their visible flame overlay needs the source's style-specific frozen flame geometry and colors. Required dependencies are respectively `Flame_1.png`, `Flame_3.png`, `Flame_13.png`, `Flame_5.png`, `Flame_4.png` and `Flame_2.png`. Off-state transparency has not been assumed from a frame number. Their bodies are available only as partial review geometry. Chandeliers have a Y −2 hanging offset; lanterns and banners also move up another eight pixels below a non-hammered platform. The six incomplete lighting types are excluded from admitted coverage and the minimal asset list.

Pylon 597 needs its floating crystal from `Extra_181.png`, including the style and coordinate-dependent frame. Relic 617 needs the displayed relic from `Extra_198.png`; its pedestal is not the full object. Lihzahrd altar 237 needs `SunOrb.png`; rainbow boulder 711 needs its separate halo geometry; glow tulip 656 needs `Glow_329.png`. These types are left to other planners, not represented as completed empty bodies.

Item frames 395, weapon racks 471, food platters 520, display dolls 470, hat racks 475 and display jars 698 use tile-entity item data and item/equipment textures. The current tile-only decoder does not establish those contents. Their absence is a data dependency and must never be inferred as an empty display. These types are not admitted here.

The only source-hidden particle emitters identified in the established implementation remain 373, 374, 375, 461 and 709. This batch adds no invisible-emitter classifications. Player effects, emitted particles, moving wind and ambient lighting are outside the static baseline; visible object overlays are not silently discarded under that description.

## Validation and assets

Run `node --test test/static-furniture-next.test.mjs`. The synthetic tests cover geometry, wrapping, negative inputs, all beam cardinal masks, diagonal cuts, slope and coating boundaries, halo handling, large-object partitions, herb species conditions, versioned header reads and malformed section limits. A bounded missing-texture test verifies that the shared frame preparation path records failures before allocating a canvas and obeys its frame budget.

With the authorized public `fixtures/example-world.wld`, the test scans all candidate cells and deduplicates their crop rectangles. Set `EXPLORETV_FURNITURE_CROP_REPORT=1` to write `artifacts/furniture-next-crops.json`, containing the world hash, counts, exact minimal assets, each asset's maximum crop boundary, every unique crop, and actual PNG bounds when the asset exists. No absent PNG is counted as verified.

Initial geometry audit: 22,593 candidate cells in 81 types; 1,747 lighting-fixture cells explicitly rejected for missing flame implementation; 20,846 drawable candidate cells; 1,730 unique crops requiring 76 PNGs. These counts describe the candidate module, not published renderer coverage. All 76 required PNGs have now been fetched and checked against the actual crop bounds. The report and test will validate real image dimensions after the parent obtains only the required assets.

# Miscellaneous static bodies and source-hidden emitters

`planStaticMisc(region,x,y,tile,options)` is an original geometry planner for explicitly inspected families. It returns `{commands:[normalizedSprite,...]}`, `null` for another family, or `{unsupported:reason}`. Particle emitters return `{commands:[],hidden:true,fidelity:"source-hidden",reason:"particle-emitter-without-tile-body"}`. Source-hidden cells are successfully classified and must not be counted as unsupported or missing assets.

The caller must preserve every sprite's asset, type override, paintId override, vertexColor, offsets, dimensions and ordering. The root tile's visible-cell count increases once, not once per command. The input world records are never changed. Missing saved frames, unknown track indices, unsupported crystal orientations and object slope/half-block inputs are explicitly rejected.

## Supported static behavior

- 373, 374, 375, 461 and 709 are water, lava, honey, sand and shimmer particle emitters. The inspected tile loop invokes `EmitLiquidDrops` and immediately continues. There is no tile-body sprite to draw. Their omitted moving particles are outside a static texture scene, and no `Tiles_<id>.png` is required.
- 233 detritus keeps each saved 16×16 object segment at Y +2 with wind fixed to zero. 444 beehives keep their saved 16×16 segments at Y −2. This latter offset comes from the multi-tile hanging-object drawing path, not from the generic draw-data method. 484 rolling cactus keeps saved 16×16 segments with no displacement.
- 485 antlion larvae keep 16×16 segments at Y +2. Their animation clock is zero, but the source adds the object's world-coordinate phase modulo four. That phase advances atlas Y in 36-pixel steps and must remain consistent across a 2×2 object's cells and across render chunks.
- 3, 24, 61, 71, 110, 201, 637 and 703 plants use 16×20 saved sprites; 20 uses 16×18. Their X mirror depends on even absolute world X. The wind angle is zero. Player discovery effects, particles and dynamic brightness are omitted under the unlit static baseline.
- 129 ordinary crystals use saved 16×16 sprites with attachment-specific ±2-pixel offsets and vertex color (255,255,255,100). This is not equivalent to opacity 100/255: premultiplied RGB is preserved, so alpha splitting must retain the super-alpha contribution. Shimmer styles at frameX ≥324 select a six-frame static animation cycle, draw four neighboring halo crops at source Y +72, then the center. The halo's hue includes world position at time zero; temporal color motion is stopped. The small HSL conversion is original JavaScript and is not a claim of bit-identical floating-point parity with a GPU game screenshot.

## Minecart tracks

314's frameX and frameY are **indices**, not atlas pixel coordinates. Valid track IDs are 0–35, with frameY=−1 meaning no back track. The explicit metadata table maps to 16×16 crops on an irregular 18-pixel grid. `staticTrackRectangle` also exposes decoration IDs 36–39; these cannot be used as front/back track IDs.

The draw order is a possible rope behind the track, back track, front track, back-left/front-left lower joins, back-right/front-right lower joins, then a front-only bumper. Lower joins draw at Y +16; bumpers at Y −16. Pressure-track and booster styles remain distinct, with the booster clock frozen at zero. Straight and sloping track shapes come from their own atlas crops.

Paint on a switching track follows source-derived left/right connection routing rather than assigning the root cell's paint to both branches. Shared left connections prefer right-neighbor paint; shared right connections prefer left-neighbor paint. The remaining branch intentionally preserves the reference's asymmetry when only a right neighbor is painted. Neighbors must be active track cells; an actuated active track still contributes.

A rope behind a track requires an active rope endpoint above and below with no inactive gap. The upper endpoint is at most five cells above and the total endpoint span is at most six cells. Its type and paint select the rope atlas; the crop is (90,18×((worldX+worldY)%3),16,16). The caller should provide a five-cell render halo, either in the primary region or `region.context`. Without outside context, endpoints outside the region cannot be inferred. Required rope PNGs depend on actual endpoints; they are not guessed from a track ID.
